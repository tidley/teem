## Same-task completion without approval loops

Do the approved job, then report its outcome. Reuse recorded scope and action
approval; a new stage or harness failure does not require the user to repeat it.
Handle routine diagnosis, local repairs, non-destructive checkout preparation,
verification and supported bounded continuation within approved access and
repository rules. Do not turn these into a request for a copy-and-paste approval.

A Teem coordination error is not a blanket block on local engineering or Git.
Continue permitted inspection, implementation, tests and independent reviews.
With existing commit/push authority and the required reviews/checks, use ordinary
scoped Git operations on the approved checkout when appropriate. Do not claim
Teem qualification that did not occur, edit a retained managed snapshot, or
publish unreviewed work. Keep requested changes separate from unrelated files.

For a stale enablement receipt, use `teem_refresh_enablement` to refresh only this
host-authenticated chat through verified native/Herdr identity. It needs no typed
approval formula and starts no work. Never forge identity or edit Teem state
through raw SQL, shell or ad-hoc API writes. If supported recovery is missing,
repair that limitation where the task's authority covers it, then verify/review
the repair before use; do not call a missing implementation "missing consent".

When a hold cites an issue but the workflow ID is unknown, use native
`teem_issue_status` with the exact issue reference. It returns bounded historical
coordination metadata for this chat's native home directory, including the
responsible coordinator and recorded stop states. It does not require optional
enablement or grant management/full-evidence access. Do not ask the user to locate
an ID available through this lookup. The recorded coordinator remains responsible
for stop confirmation and recovery; a missing native session is not proof of stop.

Preserve all existing safety gates: required checks and two independent reviews,
remaining revision budgets, ownership/handoff restrictions, uncertain executions,
human-only permission cards, private data and separately authorised external,
destructive, publication, deployment and device actions. Never replay uncertain
inputs, discard work, invent approval or silently expand scope. If a genuine gate
is missing, report the exact technical/evidence/authority gap and the smallest
necessary decision, not another blanket request to continue an approved job.

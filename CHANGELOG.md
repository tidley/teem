# Changelog

## Unreleased

### 2026-11-16

- Pin declared review prerequisite files and supply local read-only copies and
  preloaded guidance to workers and reviewers, with launch-time preflight checks.
- Separate access/setup-blocked review verdicts from source findings and code
  corrections. Add explicit unchanged-candidate review requalification without
  implementation workers, parent rewrites or automatic counter renewal.
- Show actionable result reasons first with distinct scrollable sections and
  worker claims below recorded verification; name automatic correction limits.
- Honour explicit human review waivers in agent instructions without fabricating
  passing reviews or expanding commit/push, runtime or device authority.

- Expand `/teem-result` into a scrollable retained-evidence view: worker-reported
  changes and limitations, named checks, snapshot-bound review verdicts and
  findings, and separate local integration, publication and deployment status.
  Keep claims distinct from verification, show missing or shortened evidence,
  and preserve read-only retrieval and legacy projection support.

### 2026-11-15

#### Changed

- Make routine in-scope implementation and regression correction autonomous, with
  concise explanations of broken behaviour, decisions, verification and limits.
- Organise the default Foreman instructions into outcome, authority, execution,
  evidence and reporting; remove repeated guidance without widening permissions.
- Allow one authenticated native chat to coordinate authorised work in another
  configured project. Preserve the home identity, target policy and native owner.
- Make completion guidance respect existing explicit task approval instead of
  blocking already-authorised follow-on integration. Completion itself grants no
  authority; local commits, publication and deployment keep their separate gates.
- Align onboarding and safety documentation with optional native enablement,
  cross-project dispatch, explicit local commits and opt-in trusted worker shell.

#### Fixed

- Preserve native-chat provenance independently of real Herdr terminal bindings,
  including cross-project queued progression without optional enablement.
- Continue accepting exact historical completion receipts without resending them;
  reject changed payload text, metadata or native identity.
- Include previously local supervisor repairs: complete independent local clones
  without repeated repacking, guarded continuation of proven unlaunched Git
  preparation failures, and preserved stopped/unseeded handoff candidates.
- Add qualification-only recovery for eligible retained setup failures, explicit
  setup-blocked implementation handoff, and blocked-review correction handoff.
  Each preserves the old candidate and requires fresh checks and two reviews;
  see [recovery contracts](docs/ISSUE20_RECOVERY.md).
- Include shared native installation and chat-receipt/progress routing repairs.
- Check Git identity before integration writes, preserve configured signing, and
  reconcile uncertain commit outcomes by reads rather than a second commit.
- Keep the latest result visible outside a hidden/collapsed sidebar and expose
  local result retrieval through `/teem-result`.

#### Verification and limits

- Native tests cover authority wording, configured-project admission/progression,
  candidate/check/review contracts, historical notification compatibility and
  installer preservation. Bun tests cover the OpenCode adapter.
- Prompt tests establish instruction contracts, not guaranteed model behaviour.
  Qualification is not integration, installation, runtime validation or publication.
- This is a source update, not a versioned binary release or firmware deployment.
  Existing uncertain workflows and pending work are not automatically replayed.
